1. Joins no PostgreSQL

Os JOINs relacionam diferentes tabelas do banco de dados — o mesmo tipo de combinação que você já fazia com .merge() no Pandas desde a Semana 05. Para criar um JOIN, o primeiro passo é descobrir qual coluna as duas tabelas têm em comum.

Tipo de JOINO que faz
INNER JOINTraz só as linhas que têm correspondência nas DUAS tabelas
LEFT JOINTraz TODAS as linhas da tabela da esquerda, mesmo sem correspondência na direita

Nesta semana você pratica o INNER JOIN; os outros tipos você aprofunda na Semana 10.

-- pedidos com o nome da categoria do produto
SELECT pedidos.cliente, pedidos.item, produtos.categoria, produtos.preco
FROM pedidos
INNER JOIN produtos ON pedidos.item = produtos.item;
🛠 JOIN + WHERE + GROUP BY: um JOIN pode ser combinado com qualquer outro comando que você já conhece — filtrar com WHERE, resumir com GROUP BY. A ordem de leitura continua a mesma: primeiro junta, depois filtra/agrupa.

2. Views no PostgreSQL

Cada SELECT que você roda é perdido assim que você executa outro — nada fica salvo. Uma VIEW resolve isso: ela salva uma consulta (a consulta em si, não o resultado) com um nome, pra você não precisar reescrevê-la toda vez.

-- salva a consulta com nome
CREATE OR REPLACE VIEW vw_pedidos_completos AS
SELECT pedidos.id_pedido, pedidos.cliente, pedidos.filial,
       produtos.item, produtos.categoria, produtos.preco
FROM pedidos
INNER JOIN produtos ON pedidos.item = produtos.item;

-- consulta a VIEW como se fosse uma tabela
SELECT * FROM vw_pedidos_completos WHERE filial = 'Centro';
💡 Uma VIEW não guarda dado — ela guarda a CONSULTA. Toda vez que você a consulta, o PostgreSQL roda a pergunta original de novo, trazendo o dado sempre atualizado.
✅ Antes de seguir para a Semana 10, confirme: Você sabe explicar por que um JOIN precisa de uma coluna em comum entre as tabelas, e sabe a diferença entre rodar um SELECT direto e consultar uma VIEW.
