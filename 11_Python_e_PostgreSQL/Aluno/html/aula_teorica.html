1. Instalação e Configuração: preparando seu computador

Diferente de semanas anteriores, aqui não basta um pip install. Você precisa de 2 coisas antes de escrever qualquer código de conexão:

O quêComo se instala
Biblioteca pyodbc%pip install pyodbc — normal, como qualquer biblioteca Python
Driver ODBC do SQLiteUm programa do Windows, baixado do site do fabricante e instalado como qualquer outro programa — pip não instala isso
⚠️ Erro real que você vai ver antes de instalar: se você rodar import pyodbc sem ter instalado a biblioteca, o Python devolve exatamente isto: 
>>> import pyodbc
ModuleNotFoundError: No module named 'pyodbc'

Isso não é um bug — é o Python te dizendo, com precisão, que aquela biblioteca ainda não existe no seu computador. Resolve-se instalando, nunca "corrigindo" o código.

O driver ODBC do SQLite se baixa em http://www.ch-werner.de/sqliteodbc/ (escolha a versão de 64 bits — o nome do arquivo de 32 bits tem "_w32", é o erro mais comum aqui). Depois de instalar e reiniciar o VS Code, confirme com:

-- deve aparecer "SQLite3 ODBC Driver" na lista
import pyodbc
print(pyodbc.drivers())
💡 Isso é trabalho de uma vez só. Depois que o driver aparece na lista, você não precisa reinstalar em nenhum outro notebook desta semana — é uma configuração do computador, não do projeto.

2. Por que integrar Python e SQL?

A integração entre Python e SQL permite executar comandos SQL diretamente pelo seu código, dentro do banco de dados — e já trazer o resultado pronto pra dentro de uma análise, sem sair do script.

SituaçãoO que usar
Só consultar/alterar dados manualmenteSQL direto numa ferramenta de banco
Um sistema, automação ou análise precisa ler/escrever sozinhoPython + SQL
💡 Guarde esta ideia: o pyodbc funciona com a mesma estrutura de código pra vários bancos diferentes (SQL Server, MySQL, Oracle, SQLite) — só o driver muda. O que você aprender aqui vale pra qualquer um deles.

3. Conectando ao banco com pyodbc

Toda conexão com pyodbc segue o mesmo caminho, em 3 etapas: conectar → criar um cursor → executar comandos SQL.

-- modelo genérico de conexão
dados_conexao = ("Driver={Seu_Driver};"
                "Server=SeuServidor;"
                "Database=NomeDoBanco;")
PeçaPapel
Driver={...}Só este campo usa chaves { } — exigência do ODBC, porque nomes de driver costumam ter espaço (ex: "SQLite3 ODBC Driver")
ServerEm bancos com servidor (como o PostgreSQL), é o endereço da máquina. No SQLite (sem servidor) o campo existe só porque o formato exige, mas não tem efeito real
DatabaseNo SQLite, é o caminho do arquivo .sqlite/.db
-- conexão real, cursor e primeira consulta
import pyodbc

dados_conexao = ("Driver={SQLite3 ODBC Driver};"
            "Server=localhost;"
            "Database=dataset/salarios.sqlite;")

conexao = pyodbc.connect(dados_conexao)
cursor = conexao.cursor()

cursor.execute("SELECT * FROM Salaries")
valores = cursor.fetchall()

cursor.close()
conexao.close()
⚠️ Sempre feche cursor e conexão ao terminar — isso libera o arquivo do banco pra outros programas e evita erros de "arquivo em uso" na próxima conexão.

4. Create — inserindo dados (INSERT)

O C do CRUD. O comando INSERT INTO cria uma linha nova numa tabela — aqui, um álbum novo no banco chinook.db (catálogo de uma loja de mídia digital).

-- inserindo um álbum novo, associado a um artista já cadastrado
cursor.execute('''
INSERT INTO albums (Title, ArtistId)
VALUES
('Lira Rock', 4)
''')

conexao.commit()
⚠️ conexao.commit() é obrigatório depois de qualquer INSERT/UPDATE/DELETE — sem ele, a alteração fica só na memória e nunca é salva de verdade no arquivo do banco. (O pyodbc também aceita cursor.commit(), que faz exatamente a mesma coisa — este material usa sempre conexao.commit(), pra não ter dúvida de qual dos dois usar.)

5. Read — duas formas de consultar

Existem 2 formas de trazer um resultado de volta pro Python:

FormaComo funciona
Manualcursor.execute() + cursor.fetchall() — você monta o DataFrame a partir do resultado, usando cursor.description pra pegar os nomes das colunas
Direto com Pandaspd.read_sql("SQL", conexao) — o Pandas já devolve um DataFrame pronto, numa linha só
-- forma manual
cursor.execute("SELECT * FROM customers")
valores = cursor.fetchall()
descricao = cursor.description
cursor.close()

colunas = [tupla[0] for tupla in descricao]
tabela = pd.DataFrame.from_records(valores, columns=colunas)
-- forma direta, com o modulo nativo sqlite3 (sem precisar do driver ODBC)
import sqlite3
conexao = sqlite3.connect("dataset/chinook.db")
tabela = pd.read_sql("SELECT * FROM customers", conexao)
💡 Se o sqlite3 nativo já lê o arquivo sem instalar nada, por que instalar pyodbc + driver? Esse atalho só existe porque o banco É um arquivo SQLite. Num SQL Server, MySQL ou no PostgreSQL das Semanas 08-10, esse módulo nativo não serve — você precisaria do pyodbc (ou do psycopg2, específico do Postgres) do mesmo jeito. O Passo de instalação vale pra qualquer banco real que você usar depois do curso.

6. Update — atualizando registros

O comando UPDATE altera valores de linhas que já existem.

-- corrigindo o e-mail de um cliente
cursor.execute('''
UPDATE customers SET Email='lira@embraer.com.br' WHERE Email='luisg@embraer.com.br'
''')

conexao.commit()

7. Delete — removendo registros

O comando DELETE remove linhas inteiras de uma tabela.

-- removendo um álbum pelo Id
cursor.execute('''
DELETE FROM albums WHERE AlbumId=2
''')

conexao.commit()
⚠️ Cuidado com o DELETE sem WHERE — sem essa cláusula, o comando apaga a tabela inteira, não só uma linha.
